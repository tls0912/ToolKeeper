# 007｜TransLamp — Offline Language Translator

更新日期：2026-10-02。規格版本：0.1。產品狀態：規劃中，尚未 Freeze、尚未實作。

> 沒有網路時，至少先把看不懂的文字照亮。

TransLamp 是 ToolKeeper（工具番）旗下的離線應急翻譯工具。它的目的不是取代 Google Translate、DeepL 或大型語言模型，也不追求專業翻譯品質；核心目標是在沒有網路、無法使用雲端翻譯服務的環境中，讓使用者能快速理解外文的大致意思。

產品優先服務工廠、封閉網路、維修現場、設備電腦、出差與其他網路不穩定或禁止連外的環境。

## 2. 產品要解決的問題

許多翻譯服務依賴網路，但實際工作環境不一定能連外。

典型情況包括：

- 工廠產線電腦沒有 Internet。
- 客戶現場禁止設備連外。
- 維修時看到英文 Error Message，但現場無法使用線上翻譯。
- 手冊、Log、警報訊息、設定說明只有英文。
- 出差或臨時環境網路品質差。
- 使用者不希望把內部文字、設備訊息或工作內容送到雲端。
- 有一台舊電腦，只需要一個「能看懂大概意思」的翻譯工具。

TransLamp 要把這段工作縮短成：

```text
貼上文字
   ↓
選擇語言／自動判斷
   ↓
本機翻譯
   ↓
讀懂大意
```

成功標準不是「翻得像真人」，而是：

> **原本完全看不懂的內容，經過 TransLamp 後能大致理解它在說什麼。**

## 3. 明確不是什麼

TransLamp 第一版不追求：

- 專業譯者等級品質。
- 文學翻譯。
- 商務文件精修。
- 即時口譯。
- 同聲傳譯。
- 雲端大型語言模型品質。
- AI 改寫、潤稿或摘要平台。
- CAT Tool／翻譯記憶庫平台。
- 企業翻譯管理系統。
- 全功能 PDF／Word 文件處理平台。

第一版也不因「翻譯」兩個字而直接加入：

- OCR。
- 語音輸入。
- 語音朗讀。
- PDF 排版重建。
- Office 文件格式保留翻譯。
- 網頁整頁翻譯。
- 即時攝影機翻譯。
- 字幕翻譯。
- 瀏覽器 Extension。

原則：

> **先把純文字離線翻譯做好，不要把一個應急工具長成翻譯平台。**

## 4. V1 核心範圍

### 4.1 基本翻譯

V1 至少提供：

- 純文字輸入。
- 純文字輸出。
- 來源語言選擇。
- 目標語言選擇。
- 中文 ⇄ English 雙向翻譯。
- 一鍵交換來源／目標語言。
- 一鍵複製翻譯結果。
- 清除內容。
- 基本翻譯中／完成／失敗狀態。
- 已安裝語言包狀態顯示。
- 完全離線翻譯。

來源語言自動偵測可作為 V1 規格提案，但不應成為翻譯功能的必要依賴；即使自動偵測不可用，使用者仍能手動指定語言。

### 4.2 翻譯品質定位

介面與商店文案不得暗示：

- 專業翻譯。
- 精準翻譯。
- 法律、醫療、合約等高風險內容可直接依賴。
- 與大型雲端翻譯服務品質相同。

可採用的產品說法：

> **離線翻譯結果以快速理解內容為目的，可能存在語意、術語或語序錯誤。**

對於工業術語、縮寫、設備名稱、程式碼、型號及專有名詞，V1 不保證正確翻譯。

## 5. 語言包策略

### 5.1 預設語言包

已確認：

```text
中文 ⇄ English
```

作為 TransLamp 的預設翻譯能力。

產品介面上視為一個「中文 ⇄ English」語言包，但底層允許由兩個獨立方向模型組成：

```text
zh → en
en → zh
```

使用者不需要理解模型是否單向。

### 5.2 預設下載的定義

V1 原則：

- TransLamp 本體與翻譯模型分離。
- 首次需要準備語言資源時，預設選擇「中文 ⇄ English」。
- 不因支援多語言，就在安裝包內塞入所有模型。
- 中文 ⇄ English 是預設語言能力；其他語言不自動下載。
- 是否把中英模型直接包進安裝檔，留待實際模型大小、Store 包體與更新策略驗證後決定。

因此產品邏輯應區分：

```text
App
└─ Language Packs
   ├─ 中文 ⇄ English    [預設]
   ├─ 中文 ⇄ 日本語     [按需]
   ├─ 中文 ⇄ 한국어     [按需]
   ├─ English ⇄ 日本語  [按需]
   └─ ...
```

### 5.3 其他語言

其他語言採按需安裝：

- 使用者主動選擇語言。
- 顯示下載大小。
- 顯示授權／來源資訊。
- 下載完成後才可離線使用。
- 可移除語言包以釋放空間。
- 移除語言包不影響 App 本體或其他語言。

是否提供某一語言組合，取決於：

1. 是否存在品質至少可用的模型。
2. 是否可在目標硬體合理執行。
3. 模型授權是否允許產品的實際散布方式與商業用途。
4. 模型大小是否合理。
5. 是否能建立可靠的版本與下載來源。

不能因為某模型「可以下載」就自動列為產品正式支援。

## 6. 真正無網路環境的語言包安裝

只提供 App 內線上下載，無法完整滿足「無網路環境」需求。

因此 V1 應保留兩種取得方式。

### 6.1 線上下載

有 Internet 的電腦可直接從 TransLamp 下載語言包。

流程：

```text
語言包管理
   ↓
選擇語言
   ↓
顯示版本／大小／授權
   ↓
下載
   ↓
驗證
   ↓
安裝
```

### 6.2 離線匯入

語言包可在另一台有網路的電腦取得，再透過 USB、內網檔案分享或其他允許方式搬入離線電腦。

概念格式：

```text
TransLamp.LanguagePack.zh-en.<version>.tlpack
```

副檔名與實際封裝格式尚未 Freeze。

離線匯入必須進行：

- 檔案完整性檢查。
- 語言方向確認。
- 模型版本確認。
- Runtime 相容性確認。
- 必要授權資訊存在性檢查。

不可因來源檔案名稱看起來正確就直接載入。

## 8. 模型與 Runtime 技術方向

### 8.1 候選方向

目前優先研究：

- OPUS-MT 類型的小型神經翻譯模型。
- Marian Runtime。
- Bergamot Runtime／相關本機翻譯技術。

這是**技術候選**，不是已 Freeze 選型。

產品選型優先順序：

1. 可完全離線執行。
2. CPU 即可使用。
3. 模型大小合理。
4. 啟動時間合理。
5. Windows 環境整合成本可接受。
6. 可取得清楚且可遵守的授權。
7. 中文 ⇄ English 品質足以「看懂大意」。
8. Runtime 長期維護風險可接受。

### 8.2 不以大型 LLM 為 V1 基礎

V1 不以 7B、14B、27B 等通用大型語言模型作為主要翻譯引擎。

理由：

- 模型大。
- RAM／VRAM 要求較高。
- 啟動成本高。
- 分發複雜。
- 對「離線應急看懂大意」而言屬過度配置。

若未來硬體與模型技術改變，可重新評估，但不能因此拖慢 V1。

## 9. 硬體與平台方向

### 9.1 平台

規格提案：

- Windows 10 x64 起。
- 優先支援一般桌上型與筆記型電腦。
- 不要求 NVIDIA、AMD 或 Intel 獨立 GPU。
- 翻譯核心需能在 CPU 上工作。

### 9.2 硬體目標

初期目標：

| 項目 | 方向 |
| --- | --- |
| CPU | 一般 x64 CPU |
| RAM | 4 GB 可啟動與使用；8 GB 作為較合理建議 |
| GPU | 非必要 |
| 儲存 | App 本體小型化；空間主要由已安裝語言包決定 |
| Internet | 翻譯時不需要；只在下載語言包或更新時需要 |

以上是產品目標，不是已完成 Benchmark 的正式最低需求。

### 9.3 發布前實測

正式標示最低需求前，至少用數台不同世代 Windows PC 測試：

- App 冷啟動時間。
- 模型載入時間。
- 100 字翻譯時間。
- 1,000 字翻譯時間。
- 峰值 RAM。
- 模型磁碟占用。
- CPU 高負載時的 UI 響應。
- 舊 CPU 是否出現不支援的指令集。

不能只在開發者高階電腦上測試後，就宣稱支援低階硬體。

## 11. 長文字處理

V1 以短文字、錯誤訊息、段落與手冊片段為主要場景。

不能假設底層模型可一次接收任意長度文字。

規格提案：

1. App 接收完整輸入。
2. 依句號、問號、換行及模型限制進行切段。
3. 各段分別翻譯。
4. 依原順序重新組合。
5. 保留合理換行。

應避免：

- 直接按固定字元數粗暴切在單字中間。
- 因單一超長段落造成整份翻譯失敗。
- UI 在長文翻譯時完全凍結。
- 翻譯一半失敗後把未翻譯內容冒充成完整結果。

V1 不承諾保留複雜文件排版。

## 12. 工程與技術文字的處理原則

TransLamp 的重要使用場景之一是設備與軟體訊息，因此要盡量避免破壞以下內容：

- Error Code。
- PLC Device。
- IP Address。
- Port Number。
- 檔案路徑。
- URL。
- 型號。
- 版本號。
- Hex／Byte。
- 程式碼片段。
- 變數名稱。
- 常見縮寫。

例如：

```text
PLC connection timeout. Device D100 did not respond within 3000 ms.
```

翻譯時不應把 `D100`、`3000 ms` 任意改寫。

V1 可先依底層模型自然處理；若實測經常破壞技術 Token，再加入保護／還原機制。不要一開始建立過度複雜的術語引擎。

## 13. 隱私與網路行為

核心承諾：

> **翻譯內容不需要離開使用者電腦。**

因此翻譯流程：

- 不呼叫雲端翻譯 API。
- 不上傳待翻譯文字。
- 不需要登入。
- 不因翻譯而建立遠端帳號。
- 不把使用者原文／譯文作為 Telemetry 內容。

需要網路的功能只能是明確的外部資源操作，例如：

- 語言包下載。
- App 更新。
- 語言包更新。

這些操作應與「翻譯」本身分離。

離線模式下，已安裝模型應持續可用，不因授權伺服器、帳號登入或雲端狀態失去基本翻譯能力；若商業模式未來需要授權驗證，不能破壞這項核心產品價值。

## 14. 授權與第三方模型管理

這是正式發布前的必要門檻。

### 14.1 原則

不同模型可能具有不同授權，即使它們來自同一專案，也不能假設全部條件相同。

每一個正式語言包在發布前需逐一確認：

- 模型權重授權。
- Runtime 授權。
- Tokenizer／Vocabulary 授權。
- 是否允許商業使用。
- 是否允許重新散布。
- 是否要求 Attribution。
- 是否要求附帶 License／Notice。
- 是否存在 Non-Commercial 限制。
- 是否存在 Share-Alike 或其他衍生條件。
- 模型來源是否可長期追溯。

### 14.2 禁止做法

- 不因模型「免費下載」就視為可以商用。
- 不因 GitHub Repo 是 Open Source 就推定 Model Weight 同授權。
- 不把第三方翻譯 API 的輸出大量抓取後包成自己的語言資料庫，除非條款明確允許。
- 不將來源不明的模型放進官方語言包。

### 14.3 發布資料

每個語言包應能在 App 內查看：

- 模型名稱。
- 來源。
- 版本。
- License。
- 必要 Attribution。

並在安裝檔或語言包中附帶必要法律文件。

## 15. 更新與版本管理

App 與 Language Pack 分別版本化。

例如：

```text
TransLamp App: 1.0.0
Runtime: 1.x
zh-en Pack: 2026.10.x
en-zh Pack: 2026.10.x
```

原則：

- 更新 App 不等於強迫更新全部模型。
- 更新一個語言包不影響其他語言。
- 語言包更新失敗時保留上一個可用版本。
- 下載完成但驗證失敗的 Package 不可取代現有模型。
- 離線環境可以長期使用舊模型。
- 新 App 若不支援舊模型格式，必須在更新前清楚處理相容策略。

V1 不需要自建複雜 Package Manager；但資料格式從一開始要有版本欄位。

## 16. 錯誤處理

至少區分：

| 狀態 | 使用者看到的行為 |
| --- | --- |
| 尚未安裝語言包 | 提示安裝／匯入對應語言包 |
| 語言組合不支援 | 清楚標示，不偷偷改走其他語言 |
| 模型載入失敗 | 顯示模型問題，不讓 App 整體崩潰 |
| 輸入為空 | 不執行翻譯 |
| 文字過長 | 自動分段或明確提示限制 |
| 翻譯取消 | 停止後續工作，保留原文 |
| 語言包損壞 | 拒絕載入並提供重新安裝入口 |
| 磁碟空間不足 | 下載前或安裝前提示 |
| 無網路 | 已安裝模型仍可翻譯；只有下載功能不可用 |
| Package 驗證失敗 | 不覆蓋現有正常模型 |

錯誤訊息本身要讓一般使用者看得懂，不直接把 Runtime Exception 當 UI。

## 17. 效能與 UX 原則

- 模型載入與翻譯不得阻塞 UI Thread。
- 使用者應能取消較長翻譯工作。
- 已載入的常用模型可在合理記憶體範圍內快取。
- 若模型長時間未使用，可視記憶體策略卸載。
- 不為了追求毫秒級速度加入不必要的 GPU 依賴。
- 翻譯工作一次處理一個使用者要求即可；V1 不需要大量批次平行推論。

優先順序：

```text
穩定
  >
低硬體要求
  >
簡單
  >
夠快
  >
極致效能
```

## 18. V1 驗收情境

### 情境 A：完全離線中翻英

1. 電腦已安裝 TransLamp 與中文 ⇄ English 語言包。
2. 拔除網路。
3. 開啟 App。
4. 貼上一段中文。
5. 選中文 → English。
6. 執行翻譯。
7. 得到可閱讀英文。
8. 全程不得因翻譯功能嘗試連線才能完成。

### 情境 B：完全離線英翻中

同上，以英文 → 中文執行。

### 情境 C：尚未安裝日文

1. 使用者選擇日本語。
2. App 發現對應語言包不存在。
3. 明確顯示「尚未安裝」。
4. 無網路時提供離線匯入入口。
5. 不偷偷呼叫任何線上翻譯 API。

### 情境 D：USB 匯入語言包

1. 在另一台電腦取得語言包。
2. 搬到離線 PC。
3. TransLamp 選擇匯入。
4. 驗證 Package。
5. 安裝完成。
6. 拔除 USB。
7. 該語言仍可正常翻譯。

### 情境 E：舊電腦

1. 使用一般無獨立 GPU 的 Windows 10 x64 電腦。
2. App 可正常啟動。
3. 中文 ⇄ English 可完成短段落翻譯。
4. UI 不因模型推論失去基本操作能力。

## 19. 發布前 PoC

正式進入 UI 完整開發前，先做最小技術驗證。

PoC 只需要：

- 中文 → English。
- English → 中文。
- 純文字輸入輸出。
- CPU 執行。
- 不連 Internet。

紀錄：

| 指標 | 需要實測 |
| --- | --- |
| zh → en 模型大小 | 是 |
| en → zh 模型大小 | 是 |
| Runtime 部署大小 | 是 |
| 首次模型載入時間 | 是 |
| 第二次翻譯時間 | 是 |
| 100 字翻譯時間 | 是 |
| 1,000 字翻譯時間 | 是 |
| 峰值 RAM | 是 |
| CPU 使用率 | 是 |
| Windows 10 相容性 | 是 |
| 無 GPU 可用性 | 是 |
| 基本譯文是否看得懂 | 是 |
| License／Redistribution | 是 |

品質驗證不需要建立大型 Benchmark。

先準備約 30～50 組真實應急內容即可，包括：

- Windows 錯誤訊息。
- 設備 Alarm。
- 操作手冊短段落。
- PLC／MES／自動化相關文字。
- 一般生活句子。
- 帶有型號與數字的內容。
- 中英混合內容。

判定問題很直接：

> **不用追求漂亮；只問「看完譯文後，能不能理解原文大概在講什麼？」**

如果答案多數為可以，就符合產品定位。
