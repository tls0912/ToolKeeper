## 產品定位

CabiDock 是一款 Windows 桌面自動分類工具。啟動後即可依類型整理桌面，使用者也能增加只比對檔名的關鍵字規則。

一般檔案分類群組像手機上的應用程式群組：平時縮成小方塊，點一下展開，滑鼠離開後收合。「工具番」特殊群組固定以大的展開模式顯示。

核心體驗：

> 桌面檔案自動分組，平時收起，需要時點開。

- 以簡單、順手、低維護為優先，不要求功能必須市場獨有。
- 使用預設分類即可工作，不要求先完成設定。
- 低價或免費皆可，實際售價與上架方式另定。
- 002 的桌面能力已併入 ToolKeeper 平台，由 **ToolKeeper.exe 作為單一主執行入口**；CabiDock 保留為桌面模組與功能名稱，不再要求使用者啟動第二個常駐主程式。
- Hash Checker 與 JPG／BMP／PNG → ICO 規劃為工具番本體的免費小功能；JSON Viewer 已歸入 003 — ConvAnvil。以上均不列入 002。

## 與 ToolKeeper 的整併方向

2026-09-28 起，002 的產品定位調整如下：

- 使用者端維持 **單一主執行入口：`ToolKeeper.exe`**。
- CabiDock 是 ToolKeeper 的桌面模組，保留 002 產品入口與自己的設定視窗，不再提供獨立 EXE 或開發驗證薄殼。
- ToolKeeper 負責主程式生命週期、系統匣、工具目錄、Launcher 與平台整合；CabiDock 提供桌面整理與桌面群組能力。
- 只有單獨上架的產品才有自己的 EXE，目前為 001 汗青與 003 ConvAnvil。002 CabiDock、004 Hash Checker、005 Image → ICO 均在本體內執行，各有自己的視窗與產品編號。

本輪已建立 `src/ToolKeeper.Desktop` 類別庫，保留 `CabiDock` 命名空間與既有資料格式。`src/CabiDock` 只留歷史路徑說明，EXE 薄殼已退役；正式的恢復助手由 `ToolKeeper.exe --desktop-recovery` 私有模式執行，可獨立於主程序恢復桌面，不是另一個常駐產品入口。

### 工具番專屬桌面群組

CabiDock 除了一般桌面分類外，已加入由 ToolKeeper 管理的 **「工具番」專屬群組**。

此群組與一般副檔名分類不同：

- 一般群組分類的是桌面現有檔案與捷徑。
- 「工具番」群組與主視窗使用同一產品目錄，呈現 001 汗青、002 CabiDock、003 ConvAnvil、004 Hash Checker、005 Image → ICO。
- 002／004／005 直接由宿主開啟自己的工具視窗。001／003 已安裝或找到已知本機版本時顯示「開啟」，安裝或移除後更新狀態。
- 工具不可用時，有正式 Store ID 顯示「取得」，否則保留停用的「未提供」。目前汗青有正式 Store 入口，ConvAnvil 尚無。
- 使用者不需要手動建立桌面捷徑，再等待 CabiDock 重新分類。

```text
工具番
├─ 001 汗青
├─ 002 CabiDock
├─ 003 ConvAnvil
├─ 004 Hash Checker
├─ 005 Image → ICO
└─ ...
```

此設計的目的，是讓 ToolKeeper 未來擁有大量小工具時，桌面仍只需要一個清楚的工具番入口與群組，而不是散落大量捷徑。

產品狀態每十秒、主視窗啟用與系統匣開啟時刷新，點擊前再確認。入口一律是 `toolkeeper://run/001` 至 `toolkeeper://run/005`，桌面模組將平台提供的 URI 交回 ToolKeeper 派發，不解析產品或自行啟動程序。此群組固定展開，點標題、滑鼠離開、展開其他分類皆不收合；仍可拖曳、調整大小、保存並在主螢幕恢復，列表刷新不得用小卡尺寸覆寫配置。它不寫入副檔名／關鍵字分類規則，不加入檔案分類清單，不提供檔案右鍵或拖放分類。完整實機互動仍待驗收。

## 預設分類與自訂分類

首次使用直接提供以下 **七個**分類，名稱如下。副檔名由設定檔提供，不散落在分類程式的條件判斷中。

| 預設分類 | 分類方式 | 初始副檔名預設 |
| --- | --- | --- |
| 資料夾 | 項目本身是資料夾；不以副檔名判定 | 無 |
| 捷徑 | 依副檔名 | `lnk`、`url` |
| 圖像類 | 依副檔名 | `jpg`、`jpeg`、`png`、`bmp`、`gif`、`webp`、`tif`、`tiff`、`ico`、`svg`、`heic`、`heif`、`avif` |
| 文件類 | 依副檔名，涵蓋 PDF、Office、文字及 Markdown 文件 | `pdf`、`doc`、`docx`、`xls`、`xlsx`、`ppt`、`pptx`、`txt`、`md`、`markdown`、`rtf`、`csv`、`odt`、`ods`、`odp` |
| 影音類 | 依副檔名 | `mp3`、`wav`、`flac`、`aac`、`m4a`、`ogg`、`wma`、`mp4`、`mkv`、`avi`、`mov`、`wmv`、`webm`、`mpeg`、`mpg`、`m4v` |
| 壓縮檔 | 依副檔名 | `zip`、`7z`、`rar`、`tar`、`gz`、`bz2`、`xz`、`tgz` |
| 其他 | 前面規則均未命中的項目，包括無副檔名的一般檔案 | 無；是兜底分類，不是某個特殊副檔名 |

使用者可以調整副檔名設定並新增分類。資料夾與其他保留上述特殊判定方式，不把空陣列當成「無副檔名檔案」規則。

### 副檔名重複規則

- 自訂分類可以使用預設分類已有的副檔名；**自訂分類優先**。
- 不同自訂分類不可重複使用同一副檔名。
- 發現自訂分類互相衝突時，提示該副檔名已屬於哪個自訂分類，修正後才儲存。
- 副檔名初始實作預設為不分大小寫、忽略輸入時的前置句點；例如 `.MD` 與 `md` 視為同一副檔名。
- 資料夾名稱即使含有句點，仍按資料夾項目處理，不因名稱尾端看似副檔名而套用檔案副檔名規則。

例：預設「文件類」包含 `md`，新增自訂「技術文件」並加入 `md` 是允許的；Markdown 檔案會進入「技術文件」。此後另一個自訂分類再加入 `md` 時，應提示衝突。

## 檔名關鍵字規則

- 使用者可新增「檔名關鍵字 → 目標分類」規則。
- 只比對項目檔名，不讀取檔案內容、不比對上層路徑，也不分析捷徑指向的目標內容。
- 規則由上到下依序比對，**第一個命中者生效**。
- 使用者可拖曳調整規則順序。
- 目標可選擇預設分類或自訂分類。
- 初始實作預設：不分大小寫的文字包含比對；檔名使用不含路徑的完整名稱，包含副檔名。不加入正規表示式或複合條件編輯器。

例：「發票 → 文件類」可讓 `發票_202609.png` 進入文件類；若同時命中多條關鍵字規則，以清單最上方的命中規則為準。

## 分類優先順序

需要判斷分類時，依下列順序決定唯一分類：

1. **手動指定分類**。
2. **檔名關鍵字規則**，由上至下第一個命中者。
3. **自訂分類的副檔名規則**。
4. **預設分類**，依項目類型或副檔名。
5. **其他**。

沒有副檔名可比對的資料夾，略過第三步；未被手動或關鍵字規則指定時，歸入預設「資料夾」。

正常啟動若已有有效分類紀錄，直接恢復該結果，不對每個既有項目重跑上述流程。自動分類與手動指定的結果都必須保存。

## 手動分類與分類清單

### 手動指定

- 使用者可以將項目拖至另一個群組，改變該項目的分類。
- 這是虛擬分類操作，實體檔案路徑不變。
- 手動指定優先於關鍵字、副檔名與預設分類。
- 只要項目仍在桌面，重啟程式或重新開機後保留分類結果。

### 清單保存內容

保存所有已分類項目，至少包含：

- 可對應桌面項目的識別資訊與完整路徑。
- 所屬分類。
- 分類來源：自動分類或手動指定。

分類清單、群組配置與使用者規則是不同的資料；清除某個檔案的分類紀錄不會刪除關鍵字規則或整個分類。

### 啟動時核對

| 桌面與清單狀態 | 處理方式 |
| --- | --- |
| 項目仍在桌面，已有有效分類紀錄 | 沿用原分類，不重新判斷 |
| 項目在桌面，但沒有分類紀錄 | 按分類優先順序判斷，保存新結果 |
| 清單有紀錄，確認項目已不在桌面 | 清除該項目的分類紀錄 |
| 紀錄指向的分類已不存在 | 視為沒有有效分類，重新判斷並更新紀錄 |

先成功取得桌面項目，再核對移除項目；掃描失敗不等同整個桌面為空，不可因此清空分類清單。

### 執行期間與關閉期間

- 程式執行期間觀察到項目移出桌面或被刪除：清除該項目紀錄。
- 該項目再次進入桌面：當作未分類項目重新判斷。
- 程式關閉期間的檔案移動不追蹤，也不回溯。
- 關閉期間若移出又放回，啟動時仍能對上有效清單紀錄，就沿用原分類。
- 不為追查關閉期間的移動增加常駐服務或檔案歷程機制。
- 項目重新命名的初始實作預設：若能確認為同一項目，更新紀錄路徑並保留分類；若無法對應原紀錄，依啟動核對或新項目流程處理。

### 使用者修改分類規則

使用者儲存分類副檔名、檔名關鍵字或其順序的變更時：

- 重新判斷自動分類項目，立即套用新規則並保存結果。
- 保留有效的手動指定分類。
- 若目標分類已不存在，該紀錄失效並重新分類。
- 一般重新啟動仍沿用有效分類清單，不等同使用者主動修改規則。

## 群組外觀與操作

### 已定案互動

- 一般七分類平時以手機應用程式群組般的小方塊收合顯示；工具番固定展開。
- 一般分類單擊展開內容；單擊分類標題切換展開或立即收合。工具番標題不能收合；兩種群組都可拖曳標題移動。
- 滑鼠仍在展開範圍內時保持展開；離開 3 秒後收合，期間移回即取消。
- 檔案新增、移除、重新命名時更新既有分類區，保留群組視窗與展開狀態；只有無法確認安全幾何或桌面失效時暫時恢復原生圖示。
- 項目右鍵使用 Windows Shell 的傳統完整選單，另附 CabiDock 分類子選單；支援重新命名及 F2。使用者主動的檔案操作會修改實體檔案，虛擬分類本身仍不修改檔案。
- 提供套用所有分類區的不透明度設定，30–100%，預設 100%，保存後於重啟恢復。
- 空分類隱藏，有項目時顯示；隱藏不刪除分類設定或已保存的群組配置。
- 初次啟動自動排列群組。
- 使用者可拖曳調整群組位置、調整大小；配置需保存並在下次啟動恢復。
- 拖曳標題時，距離工作區邊緣或附近可見群組的對齊位置 12 DIP 內會自動吸附；相鄰群組保留 8 DIP 間距。拉遠即可脫離，按住 Shift 暫停吸附。一般分類與固定展開的工具番皆適用，群組操作預覽採相同行為。
- 吸附只作用於拖移，不在縮放、刷新或恢復既有配置時重新排列。隱藏分類不作為吸附目標；原生桌面圖示避讓與工作區邊界限制優先。
- 群組始終位於主螢幕範圍內；主螢幕或解析度改變時，將超出可用範圍的群組移回可見位置。

### 初始 UI 預設

以下為原型採用的初始預設，可依實測調整尺寸與延遲，保持上述核心操作不變：

| 操作 | 初始預設 |
| --- | --- |
| 收合方塊內容 | 分類名稱、少量項目圖示預覽、項目數量 |
| 展開方式 | 一般分類浮動展開，不推擠其他群組；同時展開一個一般分類。工具番始終維持大的展開模式，可與一般分類同時展開 |
| 滑鼠離開 | 一般分類延遲 3 秒收合，回到群組時取消；工具番不收合 |
| 開啟項目 | 雙擊，交由 Windows 預設程式或檔案總管開啟 |
| 右鍵選單與拖曳 | 操作期間保持相關群組展開，結束且滑鼠在群組外時重新計算 3 秒 |
| 拖至另一個收合群組 | 拖曳停留時暫時展開，放下後完成手動分類；停留時間由原型調整 |
| 內容超過展開範圍 | 在群組內捲動，確保所有項目可存取 |
| 調整群組大小 | 以展開狀態調整內容區大小並保存；收合方塊採一致的初始尺寸 |

原型須區分「拖曳整個群組」與「拖曳群組內項目」，避免調整配置時意外改變分類。

## 設定視窗與系統匣

設定主視窗採用 `ToolKeeper.UI` 共用外觀，原生標題列為 `CabiDock - Desktop Organizer`。內容左上以 30 DIP 顯示 `CabiDock`，標題上方不留空白列或額外上邊距，下方以 14 DIP 顯示獨立的產品簡介。桌面接管切換與群組操作預覽兩個按鈕放在 CabiDock 自己的 `Workspace` 第一列靠右的水平工具列，設定內容接續其下；這些按鈕不放在共用標頭的 `HeaderActions`。產品簡介與副標題分開定義。共用範圍與 ToolKeeper 本體、003 一致；桌面分類群組及分類、保存、啟停邏輯仍由 CabiDock 負責。

- 正式啟動顯示只含工具列表的 ToolKeeper 主視窗；桌面設定從 002 CabiDock 列表入口或系統匣開啟。首次使用及沒有平台偏好的既有使用者預設啟用桌面，之後依保存的啟停狀態恢復。
- 未調整任何設定也能直接使用七個預設分類。
- 最小化或關閉 ToolKeeper 主視窗會隱藏至系統匣；桌面設定視窗最小化或關閉只隱藏，不終止平台與桌面工作。從系統匣「桌面設定」恢復設定視窗。
- 設定視窗關閉不代表結束程式。
- 本體系統匣提供「開啟工具番」、「桌面設定」、「啟用／暫停桌面整理」與「結束程式」。
- 「結束程式」保存狀態、停止整理、移除群組並恢復正常桌面顯示；桌面啟停狀態存於本體 `platform.json`。
- 正常關閉電腦或登出必須允許程式結束，不可被「關閉縮至系統匣」攔截。

設定介面保持單純，以同一個視窗管理：

- 分類名稱與副檔名設定、自訂分類新增。
- 檔名關鍵字及目標分類。
- 關鍵字規則的拖曳排序。
- 分類區不透明度；只修改外觀時不重新分類檔案。

## 設定檔與狀態檔

### 設定檔

分類設定使用「分類名稱 → 副檔名清單」，使用者可以新增分類。為區分自訂優先權，初始 JSON 格式分為預設分類與自訂分類兩組；關鍵字規則使用有順序的陣列。

以下只是格式與初始內容示例，不鎖定檔名、儲存位置或程式內部類別設計：

```json
{
  "defaultCategories": {
    "資料夾": [],
    "捷徑": ["lnk", "url"],
    "圖像類": ["jpg", "jpeg", "png", "bmp", "gif", "webp", "tif", "tiff", "ico", "svg", "heic", "heif", "avif"],
    "文件類": ["pdf", "doc", "docx", "xls", "xlsx", "ppt", "pptx", "txt", "md", "markdown", "rtf", "csv", "odt", "ods", "odp"],
    "影音類": ["mp3", "wav", "flac", "aac", "m4a", "ogg", "wma", "mp4", "mkv", "avi", "mov", "wmv", "webm", "mpeg", "mpg", "m4v"],
    "壓縮檔": ["zip", "7z", "rar", "tar", "gz", "bz2", "xz", "tgz"],
    "其他": []
  },
  "customCategories": {},
  "keywordRules": []
}
```

新增自訂分類時，例如在 `customCategories` 加入 `"技術文件": ["md", "markdown"]`；這可以與預設文件類重複，但不能與另一個自訂分類重複。

規則範例為 `{"keyword": "發票", "category": "文件類"}`，依 `keywordRules` 陣列順序比對。首次使用沒有自訂規則，也能按預設類型分類。

### 狀態資料

- 已分類項目清單與群組位置、大小需持久保存。
- 狀態變更後應儲存，不只依賴使用者正常退出時才保存。
- 寫入失敗不得把既有可用清單覆蓋成空清單；儲存需避免留下半份檔案。
- 實作維持本機檔案即可，不為此引入資料庫、伺服器或共用框架。

## 技術方向與必要驗證

CabiDock 的產品能力改採 **單一執行入口、內部模組化**。ToolKeeper 本體負責程式生命週期、主入口與平台層整合；CabiDock 負責桌面掃描、分類、監看、Explorer 接管、桌面群組與恢復等桌面能力。

本輪已實作的結構：

```text
ToolKeeper.exe
    │
    ├─ ToolKeeper 本體
    │   ├─ 工具目錄 / Launcher
    │   ├─ 免費小工具
    │   └─ 工具安裝狀態與啟動入口
    │
    └─ CabiDock / ToolKeeper.Desktop 模組
        ├─ DesktopScanner
        ├─ DesktopWatcher
        ├─ Classification
        ├─ DesktopTakeover
        ├─ Desktop Group
        └─ Recovery
```

CabiDock 的桌面接管程式碼保留在 `ToolKeeper.Desktop`，主視窗只派發操作意圖，`PlatformController` 組合平台與模組。正常退出與登出呼叫模組 `PrepareExit`，異常退出由獨立恢復助手保護。舊 `%LOCALAPPDATA%\ToolKeeper\CabiDock` 資料不遷移；`--data-directory` 隔離測試狀態及平台偏好，`--desktop-directory` 僅掃描指定目錄，不接管真實桌面。

### Windows 相容目標

- 使用者要求 Windows 10 盡量向舊版本相容，不能只因 UI 套件方便就任意提高最低版本。
- 目前 .NET 10 官方支援清單包含 Windows 10 1607 的企業／長期支援版本，可作為原型相容性驗證起點。
- 1607 是驗證起點，不是已承諾的產品最低版本；更早版本是否可用，須驗證執行階段與實際桌面整合。
- 最終公開的最低版本及處理器架構，以實測結果決定；官方支援範圍與本產品實測相容範圍需分開記錄。

參考：[Microsoft：Install .NET on Windows](https://learn.microsoft.com/en-us/dotnet/core/install/windows)、[.NET 10 Supported OS versions](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)（查閱日期：2026-09-22）。

### 桌面整合原型必須證明

1. 分類不改變檔案實體位置，桌面群組外沒有相同項目的重複圖示。
2. 資源回收筒等系統圖示仍可正常使用。
3. 群組屬於桌面使用情境，不長期壓在一般應用程式上方；「顯示桌面」操作正常。
4. 檔案總管重啟後可恢復桌面整合，不遺失分類清單。
5. 正常退出與異常結束後，檔案仍可存取；原生桌面顯示有可靠的恢復方式。
6. 主螢幕切換、解析度與縮放比例改變後，群組仍可操作且不遺失於螢幕外。
7. 收合、展開、捲動、右鍵選單及拖曳不互相中斷。

上述仍是驗證要求；不得以普通置頂視窗遮住桌面、搬動檔案，或把所有原生圖示隱藏卻未保留系統圖示，當作已滿足本規格。

## V1 驗收情境

| 情境 | 預期結果 |
| --- | --- |
| 首次啟動，沒有設定或分類清單 | 顯示 ToolKeeper 主視窗並預設啟用桌面；七個預設分類可直接使用，空群組隱藏 |
| 新增一般圖片、文件、影音與壓縮檔 | 按設定檔副檔名分類並保存 |
| 新增資料夾、捷徑、無副檔名檔案 | 分別按資料夾、捷徑及兜底規則處理；資料夾不遞迴 |
| 自訂分類使用預設文件類的 `md` | 允許儲存，未受更高優先規則指定的 Markdown 檔案歸入自訂分類 |
| 兩個自訂分類同時設定 `md` | 提示衝突與既有分類，不默默任選一個 |
| 一個檔名命中兩條關鍵字規則 | 第一條命中者生效；改變順序後，自動分類依新順序更新 |
| 手動拖曳項目到另一群組 | 只改分類；重新啟動仍保留，檔案路徑不變 |
| 重啟時清單已有自動分類 | 沿用結果，不因普通重啟重新分類 |
| 啟動時有新項目、也有已離開桌面的舊紀錄 | 新項目分類並保存；確認已離開的紀錄清除 |
| 執行期間移出再放回 | 先清除紀錄，返回時重新分類 |
| 關閉期間移出再放回，啟動仍對得上清單 | 沿用清單，不追查關閉期間的移動 |
| 儲存分類規則變更 | 自動分類更新，有效手動指定保留 |
| 一般分類單擊、滑鼠移出、拖曳或使用右鍵選單 | 展開與收合符合原規格；進行中的操作不被收合打斷 |
| 工具番點標題、滑鼠移出、展開其他分類、更新產品目錄 | 始終維持大模式，不影響一般分類原本互斥展開與三秒收合 |
| 工具番拖移／調大小後重啟 | 恢復已保存的展開尺寸與位置，超出主螢幕時調回可見範圍 |
| 點擊 001 至 005 入口 | 各自的 toolkeeper://run/ URI 交由本體派發；002／004／005 各開宿主內視窗，001／003 開獨立產品或取得入口 |
| 調整群組位置與大小後重啟 | 在主螢幕恢復配置 |
| 關閉設定視窗 | 系統匣仍在，分類與群組持續運作 |
| 從系統匣結束程式 | 保存狀態並恢復原生桌面使用 |
| 主視窗關閉或最小化 | 主視窗隱藏，系統匣與桌面功能持續，HASH／ICO 工作不因隱藏取消 |
| 停用桌面後重啟 | 沿用停用偏好，不自動重新接管；仍可開啟本體及桌面設定 |
| 平台偏好損毀、缺必要欄位且無健康備份 | 預設停用，保留原檔並回報保存警告 |
| 工具安裝或移除 | 主視窗與「工具番」群組同步更新開啟／取得／未提供，不建立桌面捷徑 |
| Windows 登出或關機 | 允許結束，執行退出恢復，不被隱藏至系統匣規則攔截 |

## 開發順序與待定項目

開發順序：先驗證桌面整合，再完成分類與清單保存，接著群組互動與設定介面，最後進行目標 Windows 環境驗收。

目前已將分類、保存、桌面監看、群組操作預覽、桌面附掛、原生圖示裁切與恢復抽至 `src/ToolKeeper.Desktop`，並接入 ToolKeeper 平台。先前已完成實際桌面 Shell 項目的唯讀診斷；裁切未改變 Explorer 的鍵盤選取模型，整併後的接管互動仍待實機驗收，不代表已通過桌面整合要求。已實作與待驗證範圍見 [實作狀態](../CABIDOCK-IMPLEMENTATION.md)。後續待定：

- 實測後的 Windows 最低版本、處理器架構與桌面整合方式。
- 正式售價、封裝與上架方式。

V1 不擴充為檔案管理器、實體搬檔規則引擎、AI 內容分類工具或多螢幕配置系統。
