# 002｜CabiDock

## 文件狀態

- 產品代號：**002**。
- 正式產品名稱：**CabiDock**。
- 名稱來源：`Cabinet` 取前段 `Cabi`，結合 `Dock`，表達收納與停靠。
- 更新日期：2026-09-23。
- 狀態：核心需求已定案，待桌面整合原型驗證；本文件不代表功能已完成。
- UI 數值、副檔名清單及設定檔範例屬於初始實作預設；已定案的分類、記憶與啟停規則不可自行變更。

## 產品定位

CabiDock 是一款 Windows 桌面自動分類工具。啟動後即可依類型整理桌面，使用者也能增加只比對檔名的關鍵字規則。

分類群組像手機上的應用程式群組：平時縮成小方塊，點一下展開，滑鼠離開後收合。

核心體驗：

> 桌面檔案自動分組，平時收起，需要時點開。

- 以簡單、順手、低維護為優先，不要求功能必須市場獨有。
- 使用預設分類即可工作，不要求先完成設定。
- 低價或免費皆可，實際售價與上架方式另定。
- 002 是可獨立使用的正式產品。
- Hash Checker、JSON Viewer、JPG／BMP／PNG → ICO 已另定位為工具番本體的免費小功能，不列入 002。

## 預設分類與自訂分類

首次使用直接提供以下 **七個**分類，名稱如下。副檔名由設定檔提供，不散落在分類程式的條件判斷中。

| 預設分類 | 分類方式 | 初始副檔名預設 |
| --- | --- | --- |
| 資料夾 | 項目本身是資料夾；不以副檔名判定 | 無 |
| 捷徑 | 依副檔名 | `lnk`、`url` |
| 圖像類 | 依副檔名 | `jpg`、`jpeg`、`png`、`bmp`、`gif`、`webp`、`tif`、`tiff`、`ico`、`svg`、`heic`、`heif`、`avif` |
| 文件類 | 依副檔名，涵蓋 PDF、Office、文字及 Markdown 文件 | `pdf`、`doc`、`docx`、`xls`、`xlsx`、`ppt`、`pptx`、`txt`、`md`、`markdown`、`rtf`、`csv`、`odt`、`ods`、`odp` |
| 影音類 | 依副檔名 | `mp3`、`wav`、`flac`、`aac`、`m4a`、`ogg`、`wma`、`mp4`、`mkv`、`avi`、`mov`、`wmv`、`webm`、`mpeg`、`mpg`、`m4v` |
| 壓縮檔 | 依副檔名 | `zip`、`7z`、`rar`、`tar`、`gz`、`bz2`、`xz`、`tgz` |
| 其他 | 前面規則均未命中的項目，包括無副檔名的一般檔案 | 無；是兜底分類，不是某個特殊副檔名 |

使用者可以調整副檔名設定並新增分類。資料夾與其他保留上述特殊判定方式，不把空陣列當成「無副檔名檔案」規則。

### 副檔名重複規則

- 自訂分類可以使用預設分類已有的副檔名；**自訂分類優先**。
- 不同自訂分類不可重複使用同一副檔名。
- 發現自訂分類互相衝突時，提示該副檔名已屬於哪個自訂分類，修正後才儲存。
- 副檔名初始實作預設為不分大小寫、忽略輸入時的前置句點；例如 `.MD` 與 `md` 視為同一副檔名。
- 資料夾名稱即使含有句點，仍按資料夾項目處理，不因名稱尾端看似副檔名而套用檔案副檔名規則。

例：預設「文件類」包含 `md`，新增自訂「技術文件」並加入 `md` 是允許的；Markdown 檔案會進入「技術文件」。此後另一個自訂分類再加入 `md` 時，應提示衝突。

## 檔名關鍵字規則

- 使用者可新增「檔名關鍵字 → 目標分類」規則。
- 只比對項目檔名，不讀取檔案內容、不比對上層路徑，也不分析捷徑指向的目標內容。
- 規則由上到下依序比對，**第一個命中者生效**。
- 使用者可拖曳調整規則順序。
- 目標可選擇預設分類或自訂分類。
- 初始實作預設：不分大小寫的文字包含比對；檔名使用不含路徑的完整名稱，包含副檔名。不加入正規表示式或複合條件編輯器。

例：「發票 → 文件類」可讓 `發票_202609.png` 進入文件類；若同時命中多條關鍵字規則，以清單最上方的命中規則為準。

## 分類優先順序

需要判斷分類時，依下列順序決定唯一分類：

1. **手動指定分類**。
2. **檔名關鍵字規則**，由上至下第一個命中者。
3. **自訂分類的副檔名規則**。
4. **預設分類**，依項目類型或副檔名。
5. **其他**。

沒有副檔名可比對的資料夾，略過第三步；未被手動或關鍵字規則指定時，歸入預設「資料夾」。

正常啟動若已有有效分類紀錄，直接恢復該結果，不對每個既有項目重跑上述流程。自動分類與手動指定的結果都必須保存。

## 手動分類與分類清單

### 手動指定

- 使用者可以將項目拖至另一個群組，改變該項目的分類。
- 這是虛擬分類操作，實體檔案路徑不變。
- 手動指定優先於關鍵字、副檔名與預設分類。
- 只要項目仍在桌面，重啟程式或重新開機後保留分類結果。

### 清單保存內容

保存所有已分類項目，至少包含：

- 可對應桌面項目的識別資訊與完整路徑。
- 所屬分類。
- 分類來源：自動分類或手動指定。

分類清單、群組配置與使用者規則是不同的資料；清除某個檔案的分類紀錄不會刪除關鍵字規則或整個分類。

### 啟動時核對

| 桌面與清單狀態 | 處理方式 |
| --- | --- |
| 項目仍在桌面，已有有效分類紀錄 | 沿用原分類，不重新判斷 |
| 項目在桌面，但沒有分類紀錄 | 按分類優先順序判斷，保存新結果 |
| 清單有紀錄，確認項目已不在桌面 | 清除該項目的分類紀錄 |
| 紀錄指向的分類已不存在 | 視為沒有有效分類，重新判斷並更新紀錄 |

先成功取得桌面項目，再核對移除項目；掃描失敗不等同整個桌面為空，不可因此清空分類清單。

### 執行期間與關閉期間

- 程式執行期間觀察到項目移出桌面或被刪除：清除該項目紀錄。
- 該項目再次進入桌面：當作未分類項目重新判斷。
- 程式關閉期間的檔案移動不追蹤，也不回溯。
- 關閉期間若移出又放回，啟動時仍能對上有效清單紀錄，就沿用原分類。
- 不為追查關閉期間的移動增加常駐服務或檔案歷程機制。
- 項目重新命名的初始實作預設：若能確認為同一項目，更新紀錄路徑並保留分類；若無法對應原紀錄，依啟動核對或新項目流程處理。

### 使用者修改分類規則

使用者儲存分類副檔名、檔名關鍵字或其順序的變更時：

- 重新判斷自動分類項目，立即套用新規則並保存結果。
- 保留有效的手動指定分類。
- 若目標分類已不存在，該紀錄失效並重新分類。
- 一般重新啟動仍沿用有效分類清單，不等同使用者主動修改規則。

## 群組外觀與操作

### 已定案互動

- 平時以手機應用程式群組般的小方塊收合顯示。
- 單擊群組展開內容。
- 滑鼠仍在展開範圍內時保持展開；離開後收合。
- 空分類隱藏，有項目時顯示；隱藏不刪除分類設定或已保存的群組配置。
- 初次啟動自動排列群組。
- 使用者可拖曳調整群組位置、調整大小；配置需保存並在下次啟動恢復。
- 群組始終位於主螢幕範圍內；主螢幕或解析度改變時，將超出可用範圍的群組移回可見位置。

### 初始 UI 預設

以下為原型採用的初始預設，可依實測調整尺寸與延遲，保持上述核心操作不變：

| 操作 | 初始預設 |
| --- | --- |
| 收合方塊內容 | 分類名稱、少量項目圖示預覽、項目數量 |
| 展開方式 | 浮動展開，不推擠其他群組；同時展開一個群組 |
| 滑鼠離開 | 延遲約 200 毫秒收合，回到群組時取消收合 |
| 開啟項目 | 雙擊，交由 Windows 預設程式或檔案總管開啟 |
| 右鍵選單與拖曳 | 操作期間保持相關群組展開，結束後再判斷是否收合 |
| 拖至另一個收合群組 | 拖曳停留時暫時展開，放下後完成手動分類；停留時間由原型調整 |
| 內容超過展開範圍 | 在群組內捲動，確保所有項目可存取 |
| 調整群組大小 | 以展開狀態調整內容區大小並保存；收合方塊採一致的初始尺寸 |

原型須區分「拖曳整個群組」與「拖曳群組內項目」，避免調整配置時意外改變分類。

## 設定視窗與系統匣

- 每次啟動程式，顯示的主介面就是設定視窗，同時恢復桌面分類群組。
- 未調整任何設定也能直接使用七個預設分類。
- 關閉設定視窗時，預設縮至系統匣，桌面群組與自動分類繼續運作。
- 設定視窗關閉不代表結束程式。
- 系統匣初始選單只需「設定」與「結束程式」。
- 「設定」重新開啟設定視窗；「結束程式」保存狀態、停止整理、移除群組並恢復正常桌面顯示。
- 正常關閉電腦或登出必須允許程式結束，不可被「關閉縮至系統匣」攔截。

設定介面保持單純，以同一個視窗管理：

- 分類名稱與副檔名設定、自訂分類新增。
- 檔名關鍵字及目標分類。
- 關鍵字規則的拖曳排序。

## 設定檔與狀態檔

### 設定檔

分類設定使用「分類名稱 → 副檔名清單」，使用者可以新增分類。為區分自訂優先權，初始 JSON 格式分為預設分類與自訂分類兩組；關鍵字規則使用有順序的陣列。

以下只是格式與初始內容示例，不鎖定檔名、儲存位置或程式內部類別設計：

```json
{
  "defaultCategories": {
    "資料夾": [],
    "捷徑": ["lnk", "url"],
    "圖像類": ["jpg", "jpeg", "png", "bmp", "gif", "webp", "tif", "tiff", "ico", "svg", "heic", "heif", "avif"],
    "文件類": ["pdf", "doc", "docx", "xls", "xlsx", "ppt", "pptx", "txt", "md", "markdown", "rtf", "csv", "odt", "ods", "odp"],
    "影音類": ["mp3", "wav", "flac", "aac", "m4a", "ogg", "wma", "mp4", "mkv", "avi", "mov", "wmv", "webm", "mpeg", "mpg", "m4v"],
    "壓縮檔": ["zip", "7z", "rar", "tar", "gz", "bz2", "xz", "tgz"],
    "其他": []
  },
  "customCategories": {},
  "keywordRules": []
}
```

新增自訂分類時，例如在 `customCategories` 加入 `"技術文件": ["md", "markdown"]`；這可以與預設文件類重複，但不能與另一個自訂分類重複。

規則範例為 `{"keyword": "發票", "category": "文件類"}`，依 `keywordRules` 陣列順序比對。首次使用沒有自訂規則，也能按預設類型分類。

### 狀態資料

- 已分類項目清單與群組位置、大小需持久保存。
- 狀態變更後應儲存，不只依賴使用者正常退出時才保存。
- 寫入失敗不得把既有可用清單覆蓋成空清單；儲存需避免留下半份檔案。
- 實作維持本機檔案即可，不為此引入資料庫、伺服器或共用框架。

## 技術方向與必要驗證

延續工具番的一個正式產品、一個獨立 App／Project 原則。優先評估既有 .NET 10／WPF 技術，Windows 桌面整合集中於必要的程式區域，不預先拆出多層專案或外掛系統。

### Windows 相容目標

- 使用者要求 Windows 10 盡量向舊版本相容，不能只因 UI 套件方便就任意提高最低版本。
- 目前 .NET 10 官方支援清單包含 Windows 10 1607 的企業／長期支援版本，可作為原型相容性驗證起點。
- 1607 是驗證起點，不是已承諾的產品最低版本；更早版本是否可用，須驗證執行階段與實際桌面整合。
- 最終公開的最低版本及處理器架構，以實測結果決定；官方支援範圍與本產品實測相容範圍需分開記錄。

參考：[Microsoft：Install .NET on Windows](https://learn.microsoft.com/en-us/dotnet/core/install/windows)、[.NET 10 Supported OS versions](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)（查閱日期：2026-09-22）。

### 桌面整合原型必須證明

1. 分類不改變檔案實體位置，桌面群組外沒有相同項目的重複圖示。
2. 資源回收筒等系統圖示仍可正常使用。
3. 群組屬於桌面使用情境，不長期壓在一般應用程式上方；「顯示桌面」操作正常。
4. 檔案總管重啟後可恢復桌面整合，不遺失分類清單。
5. 正常退出與異常結束後，檔案仍可存取；原生桌面顯示有可靠的恢復方式。
6. 主螢幕切換、解析度與縮放比例改變後，群組仍可操作且不遺失於螢幕外。
7. 收合、展開、捲動、右鍵選單及拖曳不互相中斷。

上述仍是驗證要求；不得以普通置頂視窗遮住桌面、搬動檔案，或把所有原生圖示隱藏卻未保留系統圖示，當作已滿足本規格。

| 執行期間移出再放回 | 先清除紀錄，返回時重新分類 |
| 關閉期間移出再放回，啟動仍對得上清單 | 沿用清單，不追查關閉期間的移動 |
| 儲存分類規則變更 | 自動分類更新，有效手動指定保留 |
| 單擊群組、滑鼠移出、拖曳或使用右鍵選單 | 展開與收合符合規格；進行中的操作不被收合打斷 |
| 調整群組位置與大小後重啟 | 在主螢幕恢復配置 |
| 關閉設定視窗 | 系統匣仍在，分類與群組持續運作 |
| 從系統匣結束程式 | 保存狀態並恢復原生桌面使用 |

## 開發順序與待定項目

開發順序：先驗證桌面整合，再完成分類與清單保存，接著群組互動與設定介面，最後進行目標 Windows 環境驗收。

目前僅完成產品規格，尚未建立 CabiDock 程式專案或完成原型。後續待定：

- 實測後的 Windows 最低版本、處理器架構與桌面整合方式。
- 正式售價、封裝與上架方式。

V1 不擴充為檔案管理器、實體搬檔規則引擎、AI 內容分類工具或多螢幕配置系統。
