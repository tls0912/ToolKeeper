# 006｜HistoLens — 歷史放大鏡

更新日期：2026-10-03。規格版本：0.2。產品狀態：規格尚未 Freeze；已開始合成資料開發預覽，真實資料研究與發布未完成。進度、免費來源及集中待決事項見 [006 實作紀錄](../HISTOLENS-IMPLEMENTATION.md)。

> 不告訴你明天會怎樣，把過去攤開給你看。

HistoLens 是 ToolKeeper（工具番）旗下的個股歷史研究工具。使用者自行挑選有興趣的股票，確認後才取得歷史資料，再透過產品提供的研究模型、可調參數與歷史案例統計，理解這檔股票過去曾經發生過什麼。

本產品不以預測、薦股、即時看盤或交易執行為核心。產品提供方便、透明、可核對的歷史統計；判讀與決策留給使用者。

## 2. 產品要解決的問題

使用者已經對某檔股票感興趣，想知道某種狀況過去發生過幾次、當時後來如何發展，卻不想逐段翻 K 線、抄資料、寫程式或先建立完整交易策略。

HistoLens 要把這段工作縮短為：

```text
選股票 → 確認資料 → 選研究問題 → 執行 → 看統計 → 回看案例
```

典型研究問題包括：

- 這檔股票連跌三天後，歷史上的後續表現分布如何？
- 成交量明顯放大時，過去發生過哪些案例？
- 價格接近前一段時間低點時，後續五日與二十日的表現有何差異？
- 歷史上曾在十個交易日內到達指定漲幅的案例有多少？
- 平均值看起來不錯，是否其實只是少數極端案例拉高？

以上都是研究問題，不是模型有效性的宣稱。產品不使用「保證獲利」「最佳買點」「現在應該買進」作為結果文案。

### 2.1 成功標準

成功不是預測命中率，而是使用者能夠：

1. 不寫程式，完成一次單一股票歷史研究。
2. 看懂研究条件、資料範圍、有效樣本數及排除原因。
3. 從統計數字點回原始歷史案例，核對計算。
4. 保存研究設定，之後用同一設定重新執行。
5. 清楚分辨歷史資料、研究假設與自己的判斷。

## 4. 使用流程與工作狀態

### 4.1 首次使用

1. 開啟 HistoLens，看到研究清單與「新增股票」。空白畫面不顯示推薦股。
2. 輸入代號或名稱，只搜尋已授權的基本資料索引，不下載歷史行情。
3. 選定股票後，顯示代號、名稱、市場、證券類型、資料來源與可取得範圍。
4. 使用者選擇研究期間，閱讀必要的資料使用提示，再按「下載資料」。
5. 下載完成後顯示實際涵蓋範圍、資料品質、缺漏及價格調整狀態。
6. 選擇內建研究模板，必要時調整參數，按「執行研究」。
7. 先看摘要，再看各期間統計與歷史案例。
8. 可保存研究設定與本次結果，不要求建立帳號才能進行本機研究。

### 4.2 後續使用

- 開啟已下載股票時先使用本機資料，不自動重新下載全部歷史。
- 明確顯示「資料截至日期」；資料舊不等於不能研究，但不可標成最新。
- 「更新資料」與「執行研究」是兩個不同動作；V1 不在研究過程中偷偷更新資料。
- 使用者變更條件後，保留上一份結果，但標示「設定已變更，尚未重新執行」。
- 更新產生新資料版本後，舊結果仍指向舊版本，顯示可重新研究，不原地換掉數字。
- 切換股票時載入該股票的設定與結果，避免 A 股票的結果留在 B 股票標題下。

### 4.3 狀態提案

| 狀態 | 介面行為 |
| --- | --- |
| 尚未下載 | 可看股票基本資料、選期間，不能執行需要行情的研究 |
| 下載中 | 顯示日期區塊／完成進度、取消入口，不顯示虛構精確百分比 |
| 驗證中 | 顯示正在檢查資料，尚未驗證的區塊不投入研究 |
| 可研究 | 顯示資料日期、調整模式與品質摘要 |
| 部分可用 | 列出缺漏、可用範圍及受影響能力；研究遵守排除政策 |
| 授權／必要資料不足 | 保留允許的檢視能力，說明不能研究或下載的原因 |
| 研究中 | 可取消；本次使用的股票、設定及資料版本固定 |
| 完成／零案例 | 分別顯示統計或「沒有符合條件的案例」，零案例不是錯誤 |
| 失敗／已取消 | 保留前次有效成果；未完成結果不可冒充完成 |

## 5. 股票清單與資料下載

### 5.1 股票識別

- 顯示名稱使用代號＋名稱＋市場，不以名稱當唯一識別。
- 內部使用穩定的 `InstrumentId`，保存市場、代號與上市期間等識別資料。
- 相同代號於不同市場、不同證券或不同存續期間，不可自動視為同一股票。
- 股票更名、轉上市／上櫃或代號重用，必須依資料來源的明確對應處理；V1 不能確認時不自動串接。
- 下市／停止交易資料的可用範圍如實揭露，不把只查得到現存股票的資料稱為完整市場歷史。

### 5.2 期間與下載確認

期間捷徑提案：1 年、3 年、5 年、10 年、自訂。全歷史僅在來源能確認最早日期且授權允許時提供。

確認畫面需區分：

- 使用者想研究的事件日期範圍。
- 模型計算需要額外下載的前置資料。
- 事件之後的觀察資料。
- 來源實際可提供的範圍及預估請求量，無法估算時不亂填。

資料來源只提供較短歷史時，不宣稱已下載完整指定期間。使用者取消後，只保留已完成驗證的區塊或既有有效快照。

### 5.3 更新與修訂

原則是「補缺漏與修訂」，而不只是查 `MAX(Date)` 後加一天。

- 記錄已下載區間、區間內缺口及最後驗證時間。
- 增量更新包含尚未取得的日期，以及供應商規則要求回補的近期修訂範圍。
- 提供使用者觸發的完整性檢查；歷史更正可能發生在最近日期之前。
- 公司行動、交易日曆或價格調整因子更新時，重新建立受影響的衍生序列與研究快取。
- 已驗證資料不因一次 API 空回應、解析失敗或下載取消而被清空。
- 同一來源、同一股票的相同更新重複執行，不能產生重複交易日。

### 5.4 請求控制

- 預設序列化下載，依來源公布的限制設定節流，不以大量並行縮短等待。
- 限流時遵守供應商重試指示；重試次數與延遲有限制，取消後停止排入新請求。
- 不繞過驗證碼、封鎖、付費限制或存取控制。
- 顯示離線、授權失效、查無股票、來源故障、格式改變與資料缺口等不同原因。
- 不自動偷偷切換來源；來源變更需驗證單位、調整口徑與身分一致性。

## 6. 資料模型與品質要求

### 6.1 邏輯資料結構提案

| 結構 | 主要責任與欄位 |
| --- | --- |
| Instrument | 穩定識別、代號、名稱、市場、幣別、證券類型、存續範圍 |
| DailyBar | 交易日期、原始 OHLC、成交量、可選成交金額、交易狀態、來源 |
| TradingCalendar | 市場交易日及版本，供日數計算與缺漏判斷 |
| CorporateAction | 行動類型、生效日、因子或必要欄位、来源與覆蓋範圍 |
| DataSnapshot | 股票、來源、涵蓋區間、内容雜湊、取得時間、日曆／行動版本、品質狀態 |
| ResearchDefinition | 模板與版本、條件、參數、事件期間、觀察期、採樣與價格口徑 |
| ResearchRun | 設定快照、資料快照參照、引擎版本、截止日期、有效案例、排除原因與結果 |

這是邏輯分工，不要求一張表對應一個服務或一個專案。

### 6.2 標準化

- 日期統一使用公曆日期；原始民國年轉換由 Provider 處理。
- 台股研究的日期以交易所當地交易日為準，取得時間另存 UTC，不混為同一欄位。
- 成交量標準單位提案為「股」；來源若使用張或其他單位，需明確轉換並保存原始單位資訊。
- 價格與成交金額使用十進位數值，不因顯示四捨五入而改變事件判定。
- 缺值保存為缺值；`--`、空字串或不存在的價格不可變成 0。
- 資料區分原始價格、調整後價格與調整版本，不覆寫原始 OHLC。
- 畫面、計算、匯出使用同一明確標示的幣別與單位。

### 6.3 驗證規則

- 日期需落在合法範圍且無未處理的重複值。
- 有效成交日需滿足 `High >= max(Open, Close)`、`Low <= min(Open, Close)` 及 `High >= Low`。
- 價格應為正值；成交量與成交金額不得為負值。
- 零成交、停止交易及來源只提供參考價的情況，以交易狀態表示，不假裝有可成交 OHLC。
- 缺交易日、欄位異常、公司行動資訊不足分開記錄。
- 不以一般漲跌限制硬刪異常值；合法的制度性例外或公司行動可能需要保留並查證。
- 問題資料不悄悄修成看似合理的數字；保留問題原因與來源，依研究政策排除。

## 7. 除權息、分割與價格口徑

這是發布前需完成驗證的核心依賴，不是圖表美化選項。

### 7.1 計算口徑

| 模式 | 行為與限制 |
| --- | --- |
| 原始價格檢視 | 顯示來源原始 OHLC，清楚標示未調整；不隱藏價格不連續 |
| 保守原始價格研究 | 具備完整可驗證的公司行動覆蓋後，排除研究窗口跨越相關行動的案例 |
| 已驗證調整序列研究 | 僅在來源與算法已驗證時啟用；標示涵蓋哪些分割、減資、配股或現金股利處理 |

V1 提案先採「保守原始價格研究」，避免為了趕進度自行拼出未驗證的還原價格算法。它會減少樣本，結果需列出被排除的數量。

若無足夠的公司行動資訊，不能把「查不到行動」當作「沒有行動」。可保留原始資料檢視，但不開放會被標成已通過品質檢查的正式統計結果。

### 7.2 研究窗口

- 每個模型的窗口由最早所需條件日期，延伸至該案例的觀察期末。
- 條件回看區間跨越行動，可能改變事件是否成立；不可只檢查事件後的價格。
- 符合條件但只有較長觀察期跨越行動的案例，可保留其較短、未跨越行動的統計。
- 公司行動資料完整性與排除數量必須顯示，避免使用者把保守篩選後的子樣本理解成全部歷史。

### 7.3 名詞限制

- 預設結果稱「價格變動率」，不籠統稱為實際投資報酬。
- 分割調整、含現金股利調整的價格序列與股利再投資總報酬不是同一個欄位。
- 若未建立現金流與再投資模型，不宣稱顯示總報酬。
- 僅有調整收盤價而沒有一致的調整 OHLC 時，不可拿調整收盤價配原始最高／最低價計算期間極值。
- 價格調整不代表成交量也已調整；使用量價混合條件時另行定義並驗證。

## 8. 研究設定與時間邊界

### 8.1 一次研究的必要設定

```text
股票與資料來源
事件日期起訖
研究截止日 DataAsOf
研究模板與版本
模板參數／自訂條件
觀察期 Horizons = [5, 10, 20, 60] 的子集
價格調整與資料品質政策
事件合併／重疊採樣政策
資料快照與研究引擎版本
```

### 8.2 交易日定義

- 預設以所屬市場的交易日曆計數，不以日曆天計數。
- 事件日為 `t`；事件後第一個市場交易日為 `t+1`。
- 市場休市日不占觀察期；股票停牌日不能偷偷從市場交易日序列刪掉。
- 觀察期遇停牌、缺價或缺必要 OHLC，依嚴格品質政策排除該期間的樣本，不能拿之後的第五筆資料冒充第五個市場交易日。
- 日曆來源或市場身分不能確認時，該項研究不可標為完整有效。

### 8.3 資訊時間

- 日線條件在事件日收盤後成立，特徵只可使用 `t` 及以前的資料。
- `t` 日收盤價是研究基準，不表示使用者可以先知道整天成交量，再以同一收盤價買進。
- 所有觀察結果限制在 `DataAsOf` 以前已完成的交易日。
- 事件日期上限與觀察資料上限分開；研究較早的一年，可以觀察隔年的後續價格，但不能越過使用者設定的研究截止日。
- 以過去日期回看時，不使用該截止日之後的行情、公司公告特徵或其他當時尚未出現的資訊。
- 使用今日取得的修訂資料重建過去，不等於擁有當時原版資料；必須標示「以目前資料版本回溯」，不宣稱完整 point-in-time 重建。

### 8.4 前置資料與期末不足

- 系統依條件運算樹計算所需前置長度，包含前一日條件與連續漲跌所需的額外日期。
- 前置資料不足時，案例標記不可判定，而不是把缺資料當條件不成立。
- 五日結果已完整但六十日尚未完整的案例，可以納入五日統計，不納入六十日統計。
- 未完成觀察的案例列為「後續資料不足」，不是下跌，也不是零報酬。

## 9. 研究模型與條件引擎

### 9.1 入口設計

主入口是「選研究模板」，而不是要求使用者先寫交易策略。

每個模板提供：

- 清楚的研究問題與用途。
- 可讀的條件說明、參數、公式與所需資料。
- 模型 ID、模型版本與變更摘要。
- 歷史樣本與資料限制，不提供模型勝率承諾。

作者之後可持續加入自己的研究模型。**本文件列出的模板是產品與測試用的示範提案，並非使用者已提出或驗證有效的投資模型。**

模型輸出是事件匹配結果、特徵值與原因，不輸出買賣指令、目標價或未來機率。

### 9.2 V1 條件語法提案

- 條件列由「欄位／運算子／數值」組成。
- 第一版只支援 AND，最多六個條件；不加入多層括號、任意腳本或任意函數。
- 參數需驗證範圍、單位與小數位數；錯誤時指出哪個條件不能執行。
- 保存模板副本，不覆寫內建模板；更新內建模板不改動已保存研究。
- 內建參數以研究起點為目的，不標示為「最佳參數」。

### 9.3 基本特徵定義

以下 `C/O/H/L/V` 分別代表同一計算口徑的收盤、開盤、最高、最低及成交量；`N` 為回看交易日數。

| 特徵 | 公式／定義 |
| --- | --- |
| N 日價格變動率 | `C[t] / C[t-N] - 1` |
| 前 N 日最高價 | `max(H[t-N], ..., H[t-1])`，不含事件日 |
| 前 N 日最低價 | `min(L[t-N], ..., L[t-1])`，不含事件日 |
| 距前 N 日低點 | `C[t] / PriorLow[N] - 1` |
| 相對前 N 日高點變動 | `C[t] / PriorHigh[N] - 1`；低於高點時為負值 |
| 區間位置 | `(C[t] - PriorLow[N]) / (PriorHigh[N] - PriorLow[N])` |
| 相對成交量 | `V[t] / mean(V[t-N], ..., V[t-1])`，均量不含事件日 |
| 連漲／連跌 | 逐日比較相鄰有效收盤價；平盤中斷連續計數，缺值使條件不可判定 |
| 收盤突破前高 | `C[t] > PriorHigh[N]`，相等不算突破 |
| 收盤跌破前低 | `C[t] < PriorLow[N]`，相等不算跌破 |

補充：

- 前高等於前低時，區間位置不可計算，不填 0 或 50%。
- 區間位置可小於 0% 或大於 100%，代表超出前期區間，不強制截斷。
- 距前低為負值表示已低於該低點；「接近低點」與「跌破低點」是不同問題。
- 均量為零時，相對量不可計算；不顯示無限大或隨意替換分母。
- 所有條件依計算精度判定，畫面上的四捨五入值僅供呈現。

### 9.4 內建模板提案

| 模板 ID | 名稱 | 初始參數與條件 |
| --- | --- | --- |
| HL-R001 | 接近歷史區間低點 | 前 120 日低點；距低點介於 0% 至 10%，含邊界 |
| HL-R002 | 連續下跌 | 連跌天數至少 3 日 |
| HL-R003 | 量增上漲 | 事件日收盤高於前一日；成交量至少為前 20 日均量的 1.5 倍 |
| HL-R004 | 收盤突破前高 | 收盤高於前 60 日最高價 |

這些參數皆可調整，模型邏輯需完整公開於說明頁。第一版先做少數可解釋的模板，不堆滿十幾種指標。

## 10. 事件、連續命中與重疊樣本

### 10.1 為何要定義事件

同一條件可能連續成立多天。產品必須說清楚是在數「符合條件的日數」還是「獨立的一段事件」，不能把兩者混用。

### 10.2 採樣政策提案

| 政策 | 行為 |
| --- | --- |
| 連續成立取首日，預設 | 同一條件連續成立期間只保留首日；至少經過一個可判定的不成立日才形成下一段 |
| 每個符合日 | 每日皆列入，明確標示樣本高度重疊，不視為獨立試驗 |
| 非重疊觀察窗，進階 | 依日期先後，保留最早事件；下一事件須晚於前一事件＋本次最長觀察期 |

- 使用者選的政策、原始符合日數與採樣後事件數均保存在結果中。
- 首日政策需要讀取研究起日之前的條件狀態；研究起日落在既有連續事件中，不重新創造一個首日。
- 前一日條件不可判定時，不假裝它是不成立；標記事件起點不確定並排除首日判定。
- 非重疊政策先依已知條件與日期選樣，再計算後續結果，不根據哪個案例比較好看來選擇。
- 去除重疊不等於已證明樣本獨立；V1 不由此產生顯著性或未來成功率宣稱。

### 10.3 樣本漏斗

每次研究需顯示：

```text
候選事件日期數
→ 前置資料可判定數
→ 原始符合條件日數
→ 合併／去重後事件數
→ 各觀察期的有效樣本數 N_h
```

每個觀察期另外列出排除原因：後續不足、缺價／停牌、公司行動、資料異常等。一個事件可有多個標記，但彙總以固定優先順序選一個主要排除原因，確保不重複扣數。

## 11. 統計定義與計算口徑

### 11.1 共通定義

- `P0 = C[t]`，事件日收盤研究基準。
- `h` 為觀察期的市場交易日數。
- `N_h` 為通過本次政策、資料與完整觀察檢查的有效事件數。
- V1 採嚴格樣本政策：事件後 `1..h` 需具有有效且同口徑的 OHLC；成交量僅在條件需要時要求。
- 同一觀察期的期末、極值、回撤與門檻統計使用同一組有效樣本，避免不知情地比較不同分母。
- 不同觀察期允許不同 `N_h`；每一欄都必須显示自己的分母。

### 11.2 期末價格變動率

```text
R_h = C[t+h] / P0 - 1
```

每個觀察期輸出：

- 有效樣本數。
- 算術平均值、中位數。
- 上漲、下跌、平盤的次數與比例。
- 最佳與最差期末案例。
- P10／P25／P75／P90 歷史分位數。

比例定義：

```text
上漲：R_h > 0
下跌：R_h < 0
平盤：R_h = 0
上漲比例 = 上漲次數 / N_h
```

平盤不可省略，也不可偷偷排除在分母之外。比較在結果四捨五入之前完成；價格調整精度固定並記錄於版本設定。

分位數使用排序後的線性插值：位置為 `(N_h - 1) × p`，在相鄰索引間插值；只有一個樣本時各分位數等於該樣本。分位數區間是歷史樣本分布，不是未來價格的預測區間或統計信賴區間。

### 11.3 期間最高／最低價相對變動

```text
期間最高價相對變動 = max(H[t+1..t+h]) / P0 - 1
期間最低價相對變動 = min(L[t+1..t+h]) / P0 - 1
```

- 不包含事件日盤中價格，因條件可能要收盤後才知道。
- 若整段都低於事件日收盤，期間最高價相對變動可以為負，不強制歸零。
- 「期間曾到達 +5%」與「期末收在 +5%」是兩種不同統計，不共用一個含糊的最大漲幅欄位。
- 最佳期末案例也不必然是期間最高價相對變動最大的案例。

### 11.4 收盤序列最大回撤

計算從事件日收盤到觀察期末的收盤序列：

```text
C0 = P0
Peak[j] = max(C0, C1, ..., Cj)
Drawdown[j] = Cj / Peak[j] - 1
CloseMdd_h = min(Drawdown[0..h])
```

結果為 0 或負值，畫面名稱固定為「收盤最大回撤」。它不是單純的期間最低價相對事件價，也不是精確盤中最大回撤。

日 K 無法完整重建日內高低發生順序，因此 V1 不用日內 High／Low 拼出看似精確的盤中回撤路徑。

### 11.5 價格門檻研究

門檻提案：上方 `+5%`、下方 `-3%`，均可調整；這是研究門檻，不命名為建議停利或停損。

```text
UpperHit_h = 存在 j ∈ [1,h]，H[t+j] >= P0 × (1 + UpperThreshold)
LowerHit_h = 存在 j ∈ [1,h]，L[t+j] <= P0 × (1 + LowerThreshold)
```

- 門檻觸及採包含邊界。
- 分別顯示觸及次數、比例與首次觸及交易日。
- 同一案例可能同時觸及上下門檻，兩個比例不能相加當成互斥的 100%。
- 如顯示先後順序，分為上方先、下方先、同日先後不明、皆未觸及四類。
- 當兩個門檻的首次觸及日相同，V1 保守標成「日 K 無法判定先後」，不自行選對模型有利的順序。
- 日內曾出現某價格，不代表使用者一定能成交；不將觸及比例標為交易勝率。

### 11.6 小樣本與空集合

- `N_h = 0`：顯示「無有效樣本」，平均、比例與分位數為不適用，不填 0%。
- `1 <= N_h < 30`：提示「樣本較少，結果容易受個別案例影響」。30 是介面提醒門檻提案，不是統計可靠性的保證。
- 即使樣本超過提醒門檻，仍顯示年代集中、重疊與資料覆蓋限制。
- V1 不自動輸出綜合分數、模型信心或買進機率。

## 12. 結果呈現與歷史案例

### 12.1 摘要區

固定呈現：股票、市場、資料來源、資料截至日期、事件範圍、模板與版本、價格口徑、採樣政策。

每個觀察期以緊湊表格呈現樣本數、平均、中位數、上漲／平盤／下跌比例、分位數與最佳／最差案例。

不要把最高比例放大成廣告式「勝率 80%」。推薦文案：

> 在指定資料範圍與條件下，共有 N 次可完整觀察的歷史案例，其中 M 次於事件後 h 個交易日的收盤價高於事件日收盤價。

所有示範畫面使用合成資料時，必須顯示「示範資料，非真實股票研究結果」。

### 12.2 案例列表

欄位至少包含：事件日期、事件特徵、各觀察期狀態、期末價格變動、期間極值、收盤回撤、門檻觸及狀態。

- 預設按事件日期排序，可切換由早到晚或由晚到早。
- 排序不改變統計樣本；只看上漲案例的畫面篩選不偷偷重算全體統計。
- 使用者若要從篩選結果建立新研究，需形成新的研究設定與結果，而不是混在舊結果裡。
- 允許檢視被排除的案例與原因，不能只展示成功案例。
- 點選案例後，圖表定位到事件日並標出前置區間與各觀察期末。

### 12.3 圖表提案

V1 只做理解研究所需的圖表：

- 個股價格／成交量與事件標記。
- 指定觀察期的歷史價格變動分布。
- 個別事件前後的價格路徑。

事件對齊的多案例路徑、百分位帶與同期間一般日期對照列為後續候選。若實作，路徑每個時間點需顯示有效案例數，不能把不同路徑的平均線稱為市場實際走過的線。

### 12.4 基本交互

- 圖表縮放、滑鼠提示與案例定位不觸發網路下載。
- 提供原始數值或資料表檢視，使用者不必只靠看圖猜數字。
- 漲跌除顏色外同時提供正負號或文字，配合工具番主題，不只依賴紅綠辨認。
- 研究設定、結果、排除原因可由鍵盤操作；長表格使用虛擬化。

## 14. 本機保存、版本與重現

### 14.1 保存提案

本機資料庫候選為 SQLite；具體套件於實作時檢查相容性與授權。

候選位置為 `%LOCALAPPDATA%/ToolKeeper/HistoLens/`，正式路徑依獨立 App／內建模組及封裝方式確認。

業務資料、UI 偏好、來源憑證、研究輸出與診斷紀錄分開管理。不得把 API 金鑰放在研究 JSON、CSV、日誌或 Git 儲存庫。

### 14.2 資料快照

- 更新先建立候選資料版本，通過驗證後才原子切換為目前有效版本。
- 相同資料內容與相同轉換版本應產生相同内容雜湊。
- 完成的研究固定引用資料、日曆、公司行動與調整算法版本。
- 保存研究所引用的歷史快照，前提是授權允許；不要只記一個雜湊卻覆寫所有舊資料後仍宣稱可完整重跑。
- 若使用者刪除或授權要求移除舊快照，保留允許的摘要時需標示「原始快照已移除，無法完整重跑」。
- 不以研究快取取代原始資料來源與資料品質紀錄。

### 14.3 結果快取鍵

快取鍵至少包含股票、資料快照、模板版本、參數、事件範圍、截止日期、觀察期、價格口徑、採樣政策、品質政策與引擎版本。

任何影響計算的欄位改變，都不能沿用舊數值。研究取消或失敗的中間結果不可加入正式快取。

### 14.4 刪除行為

「移出研究清單」「刪除某次研究」「刪除股票本機資料」是不同動作。

刪除資料前列出受影響的保存研究；保留其他股票與其他工具資料。V1 不做未告知的自動資料清理，之後若加入容量上限，需保護保存研究所依賴的快照。

CSV 匯入可作為資料接入候選，但「使用者提供檔案」不等於授權問題自動消失。產品需說明匯入與分享範圍，不提供取得未授權資料的方法。

## 16. 匯入、匯出與隱私

### 16.1 V1 匯出提案

優先提供研究設定 JSON，以及授權允許的統計摘要 CSV／Markdown。

匯出內容包含：產品及引擎版本、股票、模型版本、參數、資料期間、有效樣本、價格口徑、採樣政策與資料限制。

原始 OHLCV、包含可重建原始資料的案例明細及圖表輸出，未確認授權前不開放。衍生統計也要確認分享權利，不預設全部可再散布。

- JSON 匯入僅接受資料格式，不執行任意程式碼。
- CSV 匯出處理可能被試算表當公式的文字欄位。
- 保存檔案先寫暫存檔再完成替換；失敗不留下被誤認為完整的結果。

### 16.2 隱私提案

- 運算、研究清單與研究條件預設留在本機。
- V1 不加入使用者研究行為追蹤、廣告 SDK 或雲端上傳。
- 下載時來源服務可能取得必要的股票請求與連線資訊，不能因此宣稱完全匿名或完全離線。
- API 憑證使用平台安全儲存機制；刪除來源設定時可一併刪除憑證。
- 診斷匯出由使用者觸發，遮蔽密鑰、個人路徑與不必要的研究內容。

## 17. 程式邊界與工程方向

以下是責任分工，不是要求拆成六個 Project：

```text
Data Provider
    ↓
資料標準化／品質驗證／本機快照
    ↓
條件與特徵計算
    ↓
事件掃描／採樣
    ↓
歷史統計
    ↓
結果與案例 UI
```

### 17.1 最小介面責任

- `IMarketDataProvider`：來源能力、股票識別、日期覆蓋與資料下載；不直接操作 UI。
- `HistoricalDataStore`：資料版本、查詢、驗證結果與保存；不決定研究條件。
- `ResearchEngine`：以固定資料快照與研究設定產生事件及統計；不發網路請求、不下單。
- UI：協調工作與顯示結果，不各自重算另一套平均或上漲比例。

V1 優先在產品內用資料夾、少量介面及純函式隔離責任。除非有明確必要，不建立微服務、通用金融平台、動態外掛或跨產品 Common 業務層。

### 17.2 可取消與一致性

- 網路 I/O 與研究運算不阻塞 UI 執行緒。
- 每項工作有取消機制與工作 ID；舊工作完成後不得覆蓋新股票或新設定的結果。
- 資料更新與研究同時存在時，研究使用已固定快照，不讀取一半新、一半舊的內容。
- 關閉產品或宿主退出時合作式取消、清理暫存寫入；不留下預設會繼續跑的背景服務。
- 取消與失敗不覆蓋上一份完整研究。

## 19. 驗收案例與檢查矩陣

所有數值案例均為**合成資料**，不是台積電或任何真實股票的績效。

### 19.1 可手算的數值基準

案例 A：事件日收盤 `100`；後續三日 OHLC 如下。

| 日 | Open | High | Low | Close |
| --- | ---: | ---: | ---: | ---: |
| t+1 | 102 | 111 | 100 | 110 |
| t+2 | 101 | 102 | 98 | 99 |
| t+3 | 102 | 108 | 101 | 105 |

應得到：

- 三日期末價格變動 `+5%`。
- 期間最高價相對變動 `+11%`。
- 期間最低價相對變動 `-2%`。
- 收盤最大回撤 `-10%`，來源為收盤 `110 → 99`，不是 `-2%`。
- 上方 `+5%` 在第一日觸及，下方 `-3%` 未觸及。

案例 B：同一觀察期四個有效事件的價格變動分別為 `-4%、0%、+2%、+6%`。

應得到：平均 `+1%`、中位數 `+1%`、上漲 `2/4`、平盤 `1/4`、下跌 `1/4`、最佳 `+6%`、最差 `-4%`、P10 `-2.8%`、P90 `+4.8%`。

案例 C：基準 `100`，事件後某一日首次出現 `High=106、Low=96`，此前均未觸及兩個門檻。對 `+5%／-3%` 研究，兩邊都算觸及，但首次先後為「同日先後不明」。

## 21. 後續候選與研究限制

### 21.1 相似歷史搜尋

保留「最近一段走勢，找同一股票歷史相似片段」作為候選。

若實作，需先定義特徵、距離、正規化、視窗長度與重複片段排除；只能使用參考截止日之前已完整發生的片段及其可觀察結果。參考片段本身、重疊片段或觀察結果越過截止日的片段不可混進樣本。

距離分數不命名為未來上漲機率，也不任意轉成「相似度 95%」而沒有可解释算法。

### 21.2 同期間對照與年代分組

候選能力包括同一股票一般日期的價格變動對照、不同年代分組、不同市場階段標記。對照需列出各自的採樣與有效樣本數，不能把不同分母的差異直接稱為模型有效性或因果效果。

### 21.3 後續多資料源

法人、融資融券、借券、營收、財報與指數均可後續增加。新增時需處理公告時間、修訂、來源授權及與股價日曆的對齊，不能把事後財報欄位直接放回公告前的研究條件。

### 21.4 長期必須保留的限制說明

- 這是條件式歷史描述，不是完整交易策略回測。
- 樣本可能重疊、集中在少數年代或受到資料取得範圍影響。
- 反覆改參數後挑出漂亮結果，不能被產品包裝成已驗證的預測能力。
- 只研究使用者挑選的股票，不代表適用於其他股票或全市場。
- 歷史資料更正、公司行動處理及排除政策，都可能改變結果。
- 不以「歷史不代表未來」一句話取代明確的資料範圍、樣本分母與算法說明。
