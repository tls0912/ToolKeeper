## 產品定位

Windows 上極簡、快速、順手的 Markdown 文件閱讀與編輯工具。

核心需求不是建立知識庫，而是解決最直接的使用情境：

> 雙擊 `.md` → 直接預覽 → 需要時切換編輯 → 儲存 → 關閉。

產品必須比大型筆記／知識管理工具更快進入工作狀態。

---

## 品牌目標

**汗青** 不只是「另一個 Markdown Editor」。

長期目標是讓使用者形成直接聯想：

> **要開 .md？就用汗青。**

理想狀態是讓產品名稱本身成為使用習慣，就像 Notepad++ 對純文字編輯的品牌記憶一樣。

---

## UX 原則

### 1. 啟動

使用者雙擊：

```text

```

商店版先完成下述啟動授權檢查；有效時直接進入汗青，並以 **Preview Mode** 顯示文件。未封裝的開發／可攜版維持直接開檔。

不要先出現：

- 首頁
- Dashboard
- Workspace 選擇
- 資料夾樹
- 工具商城

### 2. 可視範圍最大化

汗青的 UI 應優先把畫面空間留給文件內容。

核心配置：

```text

│ 汗青 - Markdown Writer │ README.md │ Notes.md        —  □  ×   │
├────┬──────────────────────────────────────────────────────────┤
│ 👁 │                                                          │
│────│                                                          │
│ 📂 │                                                          │
│ 💾 │                  Markdown Content                        │
│ 🔍 │                                                          │
│ ✕  │                                                          │
│    │                                                          │
│ ⋯  │                                                          │
└────┴──────────────────────────────────────────────────────────┘
```

整體分成三區：

- **Top = Documents**
- **Left = Actions**
- **Center = Content**

2026-09-27（0.1.14）使用者修訂：編輯模式在文件區上方加入字型、字級與 Markdown 格式工具列；預覽模式及空白視窗隱藏此列。2026-09-28（0.1.15）使用者修訂：中央文件區在閱讀時分成「章節列表＋預覽」，編輯時分成「編輯器＋預覽」，兩欄可調整寬度。

### 3. 頂部標題列

頂部標題列同時承擔：

- 軟體主標題與副標題：`汗青 - Markdown Writer`（依 ToolKeeper [全域規則](../PRODUCT_VISION.md#21-軟體標題與副標題全域規則)）
- 文件分頁
- Windows 最小化
- Windows 最大化／還原
- Windows 關閉

文件分頁放在標題列中，避免額外占用一整行。

2026-09-28（0.1.18）實作修訂：自訂標題列與 Windows `Title` 均完整顯示 `汗青 - Markdown Writer`。標題區隨介面字型與字級配置寬度；文件分頁使用其餘空間，視窗縮小或字級變更時同步更新分頁溢出列表，不以省略號截短軟體主標題或副標題。

分頁規則：

- 顯示檔名
- 多文件以 Tab 呈現
- 未儲存文件需有清楚狀態標記
- Tab 可保留關閉按鈕，但不作為主要關閉方式

### 4. 左側直立工具列

左側工具列放置高頻文件操作。

V1 包含：

1. **More / 其他功能**
2. **New Document / 新增文件**
3. **New Window / 新增視窗**
4. **Preview / Edit Toggle**
5. **Open**
6. **Recent Files / 最近開啟**
7. **Save**
8. **Save As / 另存新檔**
9. **Export PDF**

### 5. Preview / Edit 版面切換（0.1.15 修訂）

Preview 與 Edit 不使用兩顆獨立按鈕。

使用單一 Toggle：

```text

   ↓ click
✎ Edit
   ↓ click
👁 Preview
```

兩種版面：

- **👁 = Preview Mode**：左側自動列出 H1–H6 章節，依層級縮排、點選跳轉，右側顯示排版文件。
- **✎ = Edit Mode**：左側編輯 Markdown，右側即時預覽，不顯示章節列表；上方保留字型及格式工具列。

汗青啟動與開檔時預設為 **Preview Mode**。

兩欄寬度可拖曳調整，切換版面保留編輯器內容與 Undo／Redo。

### 6. 視窗尺寸調整

左側工具列的 **More** 提供視窗尺寸子選單。

原則：

- 汗青預設開啟寬度為 **900 px**
- 900 px 為建議閱讀寬度，不是最大限制
- 使用者仍可直接拖曳視窗邊框自由調整
- 從 **More → 視窗尺寸** 可快速選擇常用視窗寬度／尺寸
- 尺寸調整不可永久占用文件可視範圍
- 後續可考慮提供「恢復 900 px 預設寬度」快速動作

### 7. 字型選擇

左側工具列提供 **Aa** 按鈕作為字型入口。

原則：

- 預設不要求使用者設定，先依語系自動選擇合理字型
- 點擊 **Aa** 後以小型 Popup / Flyout 顯示可用字型
- 選擇後立即套用 Preview Mode
- 字型設定分別保存介面、預覽與編輯器偏好，不修改 Markdown 文件內容
- 編輯模式另在文件上方提供編輯器字型與字級入口；預覽與空白視窗隱藏，側欄 Aa 仍保留三組完整設定

## V1 詳細行為規格

### Preview Mode

Preview Mode 是汗青的預設模式，也是產品第一印象的核心。

規格原則：

- 文件內容置中顯示
- **汗青預設開啟視窗寬度：900 px**
- 900 px 的設計基準為 1920 px 螢幕扣除左側工具列後，可並排兩個接近 A4 閱讀寬度的汗青視窗並保留少量留白
- 900 px 是預設值，不是最大限制；使用者可自由調整視窗大小
- Preview 內容左右留白採 **自適應**，但最少 **24 px**
- Preview 內容上下留白：**32 px**
- 文件內容區保留 **1 px 細框線 + 4 px 小圓角 + 無陰影**
- Light / Dark 均使用中性框線色，讓兩個文件並排時能清楚辨識邊界
- 預設預覽字型依 UI 語系及主題自動選擇：竹子（亮色）與竹子（深色）主題搭配「傳統文字」，使用已安裝的楷體／襯線字型，繁中優先標楷體；其他主題英文優先 Segoe UI、繁中優先微軟正黑體、日文優先 Yu Gothic
- **Preview 本文預設字級：16 px**
- **Preview 本文預設行高：1.6**
- **Preview 段落間距：0.8em**
- 字體、行高、段落間距需優先考慮長時間閱讀舒適度
- H1～H6 採 **GitHub 類似風格**：H1/H2 有分隔線，其餘主要靠字級與字重區分
- Code Block 採 **GitHub 類似風格**：淺灰／深灰底、小圓角、適度 padding，並支援 Syntax Highlight
- Inline Code 採 **GitHub 類似風格**：淡灰／深灰底、小圓角、等寬字體
- Table 採 **GitHub 類似風格**：細框線、Header 淡底色、整體清楚緊湊
- Blockquote 採 **GitHub 類似風格**：左側 4 px 灰色直線，文字稍淡
- 一般清單採 **稍微寬鬆** 的項目間距
- Task List 在 Preview Mode 顯示可互動 Checkbox；勾選狀態直接同步修改 Markdown 的 `[ ] / [x]`，並將文件標記為未儲存
- 水平分隔線 `---` 使用 **1 px 淡灰線 + 較大的上下留白**
- 圖片：小圖維持原尺寸，大圖自動縮至內容區最大寬度；點擊圖片可放大檢視
- 內部 `.md` 連結在汗青新 Tab 開啟
- 外部網址交給系統預設瀏覽器
- 一般連結樣式採 GitHub 類似的藍色連結
- Scrollbar 採一般可操作寬度；平常淡化，Hover 或捲動時變明顯
- Light / Dark 整體配色採 **GitHub Light / Dark 類似風格**
- Preview 背景與整體 Theme 維持一致，不額外製作紙張卡片陰影

Preview Mode 不顯示 Markdown 原始語法，重點是閱讀。

### Edit Mode

Edit Mode 顯示 Markdown 原始碼。

V1 原則：

- 使用等寬字體
- 支援 Markdown Syntax Highlight
- 支援行號
- 支援自動縮排
- Tab / Shift+Tab 可進行縮排與反縮排
- 支援 Undo / Redo
- 編輯內容變更後更新內部 Preview Render 結果
- 切回 Preview Mode 時立即顯示最新內容

Edit Mode 不預設與 Preview 並排。

### 文件分頁行為

- 多個 `.md` 文件預設在同一個汗青視窗內以 Tab 開啟
- 已經開啟的檔案再次被要求開啟時，切換至既有 Tab，不重複建立
- 未儲存文件需有清楚狀態標記
- 關閉未儲存文件時必須詢問 Save / Don't Save / Cancel
- Tab 過多時不可無限壓縮到無法辨識，應提供合理的 Overflow / Scroll 行為
- `Ctrl+Tab` 切換下一個文件
- `Ctrl+Shift+Tab` 切換上一個文件

### 檔案行為

- 預設支援 UTF-8
- 必須正確處理 UTF-8 BOM
- 儲存時原則上保留原檔 Encoding 狀態，避免無意義改寫
- 檔案被外部程式修改時，汗青應提示使用者重新載入或保留目前內容
- 檔案被刪除或搬移時應提示狀態，不可靜默失敗
- Read-only 檔案應顯示唯讀狀態
- 超大 Markdown 檔案不得造成 UI 長時間無回應；必要時採延遲 Render 或降級行為

## V1 可靠性、更新與隱私

### 啟動正式／試用授權（0.1.19）

- 商店版啟動先核對套件身分；試用期間每次程序啟動以 `StoreContext.GetAppLicenseAsync()` 取得 Store 授權。在建立文件主視窗、復原草稿、開檔及單一實例轉送之前完成授權處理。
- Store 回傳有效試用授權時正常使用。首次回傳有效正式授權（`IsActive && !IsTrial`）後，保存本機受保護的正式授權紀錄；同一 Windows 使用者／電腦後續啟動不再查詢 Store。
- 換機、正式紀錄遺失或失效時須重新向 Store 確認。正式紀錄有效後不再查詢，所以應用程式不會自動偵測後續退款或授權撤銷。
- 授權無效時提示購買；只有已知非預設到期時間已過時才顯示「到期」，否則顯示「沒有有效授權」。
- 使用者可前往 Store 產品 `9NHF764PXW9C` 購買，或選擇取消；兩者均結束本次啟動，不開啟編輯器、不清除復原草稿、不改動文件。購買提示不自行完成交易。
- 查詢錯誤或逾時不等於授權到期。顯示無法確認授權，提供重試或關閉；未確認有效授權前不進入文件介面。
- 沒有本機有效正式紀錄時，離線依 Store 回傳的快取授權決定是否可啟動，不另設離線寬限期，也不自行延長試用。
- 使用者已在 Partner Center 設定 **7 天免費試用**，本次未登入後台查驗。期限由 Store 管理；汗青不以首次執行日期自行計算七天，MSIX 不會自動變更 Partner Center。
- 一般未封裝的開發／可攜版略過 Store 授權查詢。正式 MSIX 以 `StoreLicenseRequired=true` 編譯並核對套件身分，將 EXE 從套件取出後也不能繞過檢查。
- 本次只檢查程序啟動，不加入使用途中到期時的儲存、購買與停用編輯流程；已執行中的視窗不會被另一個被拒絕的啟動程序關閉。
- 正式授權首次確認與後續免查詢、紀錄遺失／失效後重查、有效試用、到期、未取得授權、離線快取、查詢失敗及 Store 商品頁導向須使用實際 Store 測試發佈驗收。程式測試與套件內容驗證不能取代這些情境。

### Crash Recovery

- 汗青背景暫存未儲存內容
- 若程式異常 Crash：
  - 下次啟動提供 Recover
- Crash Recovery 暫存檔在以下情況清除：
  - 文件正常儲存後
  - Tab 正常關閉後

### Local Log

- 保留本機錯誤 Log
- Log 不自動上傳
- 不建立背景遙測上傳流程

### 更新

- App 更新主要交由 Microsoft Store
- More 提供版本資訊與「檢查版本／更新」入口
- 汗青不自行實作獨立 Updater

### 隱私

汗青 V1 原則：

- 不蒐集 Markdown 文件內容
- 不做 Telemetry
- 不建立汗青帳號；商店購買與正式／試用授權使用 Microsoft Store 帳號與服務
- 不自動上傳 Crash Report
- 使用者文件預設只在本機處理

## ToolKeeper 整合

本產品是獨立 Microsoft Store App。

ToolKeeper 本身不包含 Markdown 功能。

ToolKeeper 的行為：

```text
汗青
   ↓
URI Handler 可用？
   │
   ├─ Yes → 啟動汗青
   └─ No  → 開啟 Microsoft Store 商品頁
```

汗青應註冊自己的 URI Protocol。

暫定：

```text
toolkeeper-markpad:
```

Protocol 名稱在正式上架前可以調整。
